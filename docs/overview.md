# Overview

Authenticated pages: `/overview/products?page=1`, `/overview/bs?page=1`.
Downloads: `/overview/products/export`, `/overview/bs/export`. Export always includes all eligible headers, not just the selected page. Each header produces a uniquely numbered worksheet. All cells use explicit string binding, preserving leading zeros and preventing Action text from being interpreted as formulas.

## Oracle rollout

1. Review and run `database/sql/overview_views.sql` as the owning schema using SQL*Plus/SQLcl. It only replaces views and appends identity/parent columns. It never runs the source scripts containing DROP TABLE PURGE. Review dependent consumers of SELECT * before applying the additional columns.
2. Verify the application Oracle account can SELECT all seven INDEX_SECTION views, including the newly exposed BOM/GTIN and parent columns. Grant SELECT if the account differs from the owner.
3. Deploy the application and build frontend assets. Smoke-test both pages and downloads with the same ID in two different BOM/GTIN combinations.

The application uses an Oracle read-only transaction for a consistent snapshot. Header views select ETS_STATUS IS NULL. Products match FG_BOM + GTIN + FG_ID; BS matches BOM_BUSINESS_SUPPLY + BS_GTIN + BS_ID. Rows and duplicate headers are preserved; duplicate source rows are not silently merged. Sections are ordered by the complete parent path and component. Parent columns remain visible to distinguish reused IDs.

Y displays as 1, N as 0, NULL/empty as —. Unexpected values remain visible. Action is plain text. Missing sections are empty states. Database/query errors return a 503 page, are logged through Laravel, and prevent downloads. Download failures redirect with the existing error notification.

Page values must be positive integers. Pages beyond the last record clamp to the last page. Empty datasets display 0/0 and disable export. Header identity must be populated upstream; NULL key values match only corresponding NULL values.

Export reads each detail view once, inside the snapshot, and builds the workbook before returning it. It uses memory proportional to all exported rows; very large datasets may require a queued export in a later release. There is no automatic mock-data fallback.

## Product create actions

Products shows eight green + buttons. #1 opens an empty New Product form; the current header is used only as the return destination. #2/#3 require an editable FG DML owner. #4/#5 require an editable LV.2 path, #6/#7 an editable LV.1 path, and #8 a Type4 component from PROJ1_2_DML_SEMI_L1_COMP_M4 linked to that LV.1 in INDEX. Material type is determined by this source table, never by an ID prefix. COM on an owner disables its descendants. INDEX mock rows without corresponding DML owners cannot open create forms.

`GET /overview/products/add/{action}` validates the full BOM/GTIN/FG identity and selected path. Single paths open directly; multiple paths require an explicit modal selection. Ambiguous duplicate DML paths are unavailable. The encrypted context is bound to the authenticated user, expires after four hours, and only works on the action's allowed form/save routes. Parent fields are checked and restored from the database before saving, including a fresh COM check. Return URLs are generated by the application, never accepted from query parameters.

Save/Cancel returns to the original header using all three keys. A missing/ineligible header falls back to the first record with a notice. New Product keeps the existing Product Detail destination and adds a return link. Existing save procedures continue writing DML; no INDEX sync is introduced. Overview refresh does not guarantee newly created data is immediately visible.

**Raw Material Type4 (#7/#8):** SA has not yet provided the persistence flow. Both forms show the selected parent path and input fields, but Save is disabled. The server also rejects Raw Save instead of reporting a false success. No new write procedure or role rule is invented.

Products groups only contiguous identical parent prefixes using rowSpan, while retaining every component/status/action row and duplicates. Export merges the same parent cells and retains text flags 1/0/—. Products displays read-only checkboxes only for source Y/N; NULL and unknown values remain text. BS retains its current behavior.

Additional verification: `node --test tests/js/overviewTable.test.mjs`. Browser checks use a separate in-memory SQLite fixture for parent selection and Raw forms; live Oracle checks are read-only.
